# Bluepicca 初期体験検証レポート
## ツイ廃アルファツイッタラー目線での実装評価

> 実施日: 2026-03-31
> 検証観点: twicca / ShootingStar 使用経験者が「朝・昼・夜」の3シナリオを想定して評価

---

## 朝のシナリオ検証（通勤中・7〜9時）

### できること

- **アプリ起動・TL確認**
  ContentViewで即座にタイムラインがロード。初回は中央スピナー、リフレッシュ時は上部インジケーターで状態が明確。

- **いいね・リポストの即座操作**
  TimelineCardView で両ボタンが画面下部に常に配置。タップで即座に反応し、ローカルで状態が反映される（PostStateManager で管理）。

- **引用ポストの確認**
  QuotePostCard として表示され、タップでPostDetailViewに遷移して引用元を確認可能。UI/UXが整理されている。

- **ミュートワード設定**
  朝に「イヤなワード」を見かけたら、Settings → ミュートワード で即座に追加可能。ContentViewModelで自動フィルタリング。

### 摩擦がある

- **メディア表示がバッジのみ**
  「画像1枚」「動画」などのテキストバッジだけで、実物が見えない。twicca では TL上にサムネイル表示されていたので、タップしなくても「この画像が気になるな」という判断ができた。
  → 改善案：TimelineCardView に `EmbeddedImagesViewItem.thumb` URL を使ったコンパクトなインライン表示。高さは抑えつつ視覚的な判断ができるように。

- **いいね・リポスト後の数字が即座に更新されていない**
  PostStateManager で永続化されるが、`viewModel.post` のカウント数がサーバーと非同期。
  → 改善案：ローカルカウント（likeCount + 1）を楽観的に表示。サーバーレスポンス後に同期。

- **タイムラインがハード止まり**
  スワイプジェスチャーがない。下部のボタンを毎回狙う必要があり、視線が遠い。ShootingStar では左右スワイプで即座に操作できた。

### できないこと

- **複数フィードの切り替え**
  ホームTLの1本読みのみ。GetTimelineApi で `algorithm` パラメータが常に空文字のため、カスタムフィードが活用できない。Bluesky の強みは「複数のフィードジェネレーターを自分でコントロール」なのに、ここが機能していない。

- **ハッシュタグ検索**
  コミットログに実装の形跡があるが（commit 759fe5d）、UIからの検索窓がない。「朝、#推しキャラ タグをチェックしたい」というユースケースが完全に詰まる。

## 昼のシナリオ検証（休憩中・12〜13時）

### できること

- **TL流し読み + リアクション**
  デザイン刷新で「テキスト優先」になっており、素早く内容判断できる。一つのカード高さが適正で、スクロール感も悪くない。

- **返信を書く**
  TimelineCardView の返信ボタン → ReplyPostCardView で、リプライ先が見える形で返信入力。テキストカウント、画像添付、下書き保存すべて対応。操作感は良好。

- **プロフィール閲覧**
  TimelineCardView のアバター・ハンドルをタップ → ProfileView へナビゲート。フォロー/フォロー解除、フォロワー・フォロー一覧も表示される。ミュート・ブロック操作も ProfileView 内で実行可能。

### 摩擦がある

- **プロフィール画面が長い**
  ProfileView は ScrollView で、アバター・フォロー/フォロー数・説明 → 投稿一覧、となっている。投稿一覧が下の方で、スクロール距離が長い。twicca では「タブで切り替え」（プロフィール/投稿/メディア）だったので、瞬時に投稿だけを見られた。
  → 改善案：ProfileView にタブを追加。「概要」「投稿」「メディア」で切り替え。

- **返信後のTLが手動リフレッシュ必須**
  ReplyPostCardView で送信後に `refreshRepliesAfterPost()` は呼ばれるが、元のTLにはすぐに反映されない。戻ると古いTLが表示されたまま。
  → 改善案：投稿完了通知を ContentView で受け取り、TL の先頭に新投稿を挿入。

- **ハッシュタグ検索ができない**（朝のシナリオから継続）

### できないこと

- **検索窓がない**
  ContentView にも設定にも「検索」がない。Bluesky は AT Protocol でユーザー検索・テキスト検索に対応しているが、Bluepicca にはまだない。

## 夜のシナリオ検証（帰宅後・21〜24時）

### できること

- **じっくりTL追読**
  デザインが「テキスト優先」で、字が読みやすい。スクロール感も滑らか。長時間のTL閲覧に適している。

- **スレッド形式の投稿確認**
  PostDetailView でリプライ先が表示され、返信ボタンでリプライ鎖を辿れる。

- **ブックマーク振り返り**
  TimelineCardView のブックマークアイコンで、気になった投稿を BookmarkedPost として保存。ContentView の底部ツールバー「Bookmarks」で一覧表示。削除も可能。

- **ミュートワード整理**
  Settings → ミュートワード で、追加・削除・スワイプ削除すべて可能。

### 摩擦がある

- **スレッドの繋がりが視覚的に不明確**
  TimelineCardView の isReply バナーで「@xxxへの返信」と表示されるが、TL上で「これが同じスレッドの続き」という繋がりが見えない。複数の返信が混在するTLでは、どれが同じスレッドかが直感的に分からない。

- **画像が見えない**（朝のシナリオから継続）
  ブックマークした投稿を後で見返すときも、「画像1枚」という表示だけ。

- **引用ポストの表示領域が小さい**
  QuotePostCard は padding(10) で小さく、テキストは lineLimit(4)。長めの引用元テキストは切り詰められる。

### できないこと

- **既読位置の記憶**
  アプリを終了して再起動すると、TLの先頭に戻る。高頻度でTLを確認するツイ廃にとって、毎回「どこまで読んだ？」という手探りが面倒。

- **言語フィルタ**
  PostRecord に langs データが取得されているが、UI に反映されていない。日本語TLを読むときに、英語・中国語・韓国語の投稿が混在。

- **コンテンツラベルの表示**
  Post.labels はモデルにあるが、センシティブ投稿の警告表示がない。

## 今すぐ直すべき摩擦ポイント TOP3

### 1. ハッシュタグ検索の実装（朝・昼・夜の全シナリオで詰まる）

コミットログに実装途中の形跡があるが、UIからアクセスできない。

実装手順：
- ContentView に検索アイコン（虫眼鏡）を追加
- SearchView を新規作成、テキスト入力フィールド
- ハッシュタグ入力 → `app.bsky.feed.searchPosts` API で検索
- 検索結果を TimelineCardView で表示

**難易度：低。すぐできる。**

---

### 2. インライン画像表示（判断できない）

現状は「画像1枚」というテキストバッジのみ。EmbeddedImagesViewItem.thumb URL は既に取得済み。

実装手順：
- TimelineCardView で、メディアバッジの下に画像グリッド（4画像まで）を表示
- `AsyncImage` + `frame(maxHeight: 200)` で高さを制限
- タップでフルサイズビューへ遷移

**難易度：低。データは既にある。**

---

### 3. カスタムフィード切り替え（Bluesky唯一の強みを活かす）

GetTimelineApi で algorithm が常に空文字。

実装手順：
- `app.bsky.feed.getFeedGenerators` API でユーザーが登録したフィード一覧を取得
- ContentView にタブまたはドロワーUIで表示
- タップでフィードジェネレータ URI を algorithm パラメータに渡す

**難易度：中。API 追加が必要。**

## ロードマップへの追加提案

### 「実装途中で止まっている」機能

- **ハッシュタグ検索**：commit 759fe5d に実装途中の形跡。UIから検索窓にアクセスできず。完成させてContentViewに統合すれば低コストで高効果。

### ロードマップ未掲載だが今回の検証で発見した課題

1. **楽観的更新（Optimistic Update）**
   いいね・リポスト時に、ローカルで即座にカウント数を +1。現状は「ボタン色は変わるが数字は遅延」という違和感がある。

2. **返信投稿後の TL 自動更新**
   ReplyPostCardView で投稿完了後、ContentView に通知を渡してTL先頭に新投稿を挿入。「投稿したのに見つからない」という混乱を回避。

3. **プロフィール画面のタブ化**
   「概要」「投稿」「メディア」「いいね」で切り替え。現状はScrollViewで全部が縦に長く表示される。

4. **スレッドビュー（時系列表示）**
   PostDetailView で「このスレッドの全投稿を時系列で表示」するモード。現状は個別投稿をタップして辿る必要があり、長いスレッドでは手間。

## 結論

Bluepicca は「iOS ネイティブな Bluesky クライアント」として、**デザイン・基本的な操作性は及第点**。

だが **「ツイ廃が使いこなせるレベル」には、あと1ステップ足りない**。

- **検索がない** → 情報探索ができない（最重要）
- **複数フィードが切り替えられない** → Bluesky の強みを活かせない
- **メディアが見えない** → 判断が遅い
- **スワイプジェスチャーがない** → 操作が遅い

基礎はしっかりしているので、あと3〜4つの機能実装で一気に化ける可能性がある。
