# パワーユーザー向けTL体験 ロードマップ

> ツイ廃・アルファツイッタラー（twicca / ShootingStar 使用経験者）目線での分析
> 作成: 2026-03-30 / 最終更新: 2026-03-31（体験検証レポートを反映）

## 基本方針

かつてのTwitterでできていた全機能の再現は不可能。ただし、Bluesky（AT Protocol）の仕組みを活かしながら**同等の体験**を実現することを目指す。

ツイ廃が求めるTLの本質は以下の3点：
- **TLを自分でコントロールできる**（twicca の思想）
- **TLを読む流れを止めずにアクションできる**（ShootingStar の思想）
- **文脈を失わずに会話を追える**（Twitterの会話ビュー）

## 🔴 最優先｜ないと「読めない・追えない」

### 1. ハッシュタグ検索

**なぜ必要か**
「朝・昼・夜」の全シナリオで詰まる機能。コミットログに実装途中の形跡（commit 759fe5d）があるが、UIからアクセスできない。検索がなければ情報探索が一切できない。

**現状**
実装途中で放置。ContentView に検索窓がない。

**Blueskyでの実現**
- ContentView に検索アイコン（虫眼鏡）を追加
- SearchView を新規作成、テキスト入力フィールド
- ハッシュタグ入力 → `app.bsky.feed.searchPosts` API で検索
- 検索結果を TimelineCardView で表示

**難易度：低。実装途中のコードがある。**

---

### 2. カスタムフィードの切り替え

**なぜ必要か**
ツイ廃はリストを複数持ち、用途によって切り替えていた。Blueskyのカスタムフィードはまさにこの機能の後継にあたるが、現状は「ホームTLの1本読み」しかできない。Bluesky最大の強みを使わないのはもったいない。

**現状**
`GetTimelineApi` の `algorithm` パラメータが常に空文字。

**Blueskyでの実現**
- `app.bsky.feed.getFeedGenerators` でユーザーが保存済みのフィード一覧を取得
- タブまたはドロワーで切り替えUI
- `algorithm` に feedGenerator の AT URI を渡すだけでTLが切り替わる

---

### 3. スワイプジェスチャー

**なぜ必要か**
ShootingStarが証明した体験：TLを読む流れを止めずにアクションできること。現状はいいね・リポストのたびに視線を下部ボタンに移す必要がある。

**Blueskyでの実現**
- `TimelineCardView` に `.swipeActions` または `DragGesture` を追加
- 左スワイプ → いいね
- 右スワイプ → リポスト
- 長押し → アクションメニュー（引用・返信・シェア等）

---

## 🟡 高優先｜これがあると「このアプリを選ぶ理由」になる

### 4. インライン画像表示

**現状**
「画像1枚」「動画」などバッジ表示のみ。タップしないと内容がわからない。TL流し読み中の判断ができない。

**実現**
`EmbedImagesViewItem.thumb` URL はすでにモデルに存在。`AsyncImage` でカード内に表示するだけ。高さは `frame(maxHeight: 200)` で制限。

---

### 5. 既読位置の記憶

**なぜ必要か**
高頻度でTLを確認するツイ廃にとって「どこまで読んだか」の管理は重要。多くのTwitterクライアントが持っていた機能。

**実現**
- 最後に見た投稿の URI を UserDefaults に保存
- 再起動・フォアグラウンド復帰時にその位置にスクロール
- 未読件数の表示も可能（フォアグラウンド復帰時に差分計算）

---

### 6. スレッドの繋がりの表示

**現状**
連投スレッドがTL上で個別のポストとして並ぶだけ。「これが同じスレッドの続き」という視覚的な接続がない。

**実現**
`FeedItem.reply.root` と `FeedItem.reply.parent` がすでに取得されている。
スレッドの一部と判定されたポストに「↑ スレッドを見る」バッジを表示し、タップでルートから表示。

---

### 7. リプライ制限（Threadgate）の表示

**現状**
`Post.threadgate` と `Viewer.replyDisabled` がモデルに存在するが UI で未使用。返信できないのに返信ボタンが表示されている。

**実現**
- `replyDisabled == true` のとき返信ボタンをグレーアウト
- 「フォロワーのみ返信可」等のバッジを表示

---

### 8. 楽観的更新（Optimistic Update）

**現状**
いいね・リポスト時、ボタン色は即座に変わるがカウント数の表示は遅延している。「反応した実感」が薄い。

**実現**
- いいね・リポストタップ時にローカルで即座に `likeCount + 1`（または `-1`）
- サーバーレスポンス後に同期、失敗時はロールバック
- PostStateManager の既存パターンを踏襲

---

### 9. 返信投稿後のTL自動更新

**現状**
ReplyPostCardView で送信後に `refreshRepliesAfterPost()` は呼ばれるが、元のTLには反映されない。戻ると古いTLが表示されたまま。「投稿したのに見つからない」という混乱が起きる。

**実現**
- 投稿完了通知（NotificationCenter または Combine）を ContentView で受け取り
- TL の先頭に新投稿を挿入するか、TL をリフレッシュ

## 🟢 中優先｜体験を磨く

| 機能 | 現状 | 実現方法 |
|------|------|----------|
| 言語フィルタ | `PostRecord.langs` 取得済みだが未使用 | 設定でフィルタする言語を選択 |
| コンテンツラベルの表示 | `Post.labels` 取得済みだが未使用 | センシティブ投稿のぼかし・警告表示 |
| リンクプレビューの説明文 | `EmbeddedExternalViewItem.description` 未表示 | カード展開時に表示 |
| プロフィール画面のタブ化 | ScrollView で縦に長い | 「概要」「投稿」「メディア」タブで切り替え |
| スレッドビュー（時系列） | 個別投稿を辿る必要がある | PostDetailView でスレッド全体を時系列表示 |
