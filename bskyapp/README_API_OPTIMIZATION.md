# API最適化実装ガイド

## 概要
このドキュメントでは、BlueskyアプリのAPI呼び出し回数を削減し、429エラーを防ぐために実装した最適化機能について説明します。

## 実装した最適化機能

### 1. キャッシュシステム (`Utils/CacheManager.swift`)

#### 汎用キャッシュマネージャー
- TTL（Time To Live）付きのメモリキャッシュ
- スレッドセーフな実装
- 期限切れキャッシュの自動削除

#### タイムライン専用キャッシュ
- 1分間のキャッシュ有効期間
- 初回読み込み時のみキャッシュを使用
- リフレッシュ時にキャッシュをクリア

#### プロフィール専用キャッシュ
- 5分間のキャッシュ有効期間
- ユーザーごとにキャッシュを管理
- フォロー状態の変更時にキャッシュを更新

### 2. レート制限管理 (`Utils/RateLimitManager.swift`)

#### レート制限設定
- タイムライン: 5分間に30回
- プロフィール: 5分間に20回
- いいね: 5分間に50回
- フォロー: 5分間に10回

#### SafeAPIExecutor
- API呼び出し前のレート制限チェック
- 429エラー時の自動リトライ
- 指数バックオフによる待機時間調整

### 3. バッチ処理システム (`Utils/BatchProcessor.swift`)

#### バッチ処理対象
- いいね/いいね取り消し
- リポスト/リポスト取り消し
- フォロー/アンフォロー

#### 処理方式
- 2秒間隔での定期処理
- 最大5件のアクションを並列処理
- 即座にローカル状態を更新（楽観的更新）

### 4. 最適化されたAPI呼び出し

#### タイムライン取得の改善
- 取得件数を100件から50件に削減
- キャッシュによる重複取得の防止
- ページネーション対応による増分読み込み

#### プロフィール取得の改善
- キャッシュによる重複取得の防止
- フォロー状態変更時の不要な再取得を削除

#### いいね・リポスト処理の改善
- バッチ処理による API呼び出し回数の削減
- 楽観的更新による即座のUI反映

## 使用方法

### キャッシュの使用
```swift
// タイムラインキャッシュ
TimelineCacheManager.shared.cacheTimeline(timeline)
let cachedTimeline = TimelineCacheManager.shared.getCachedTimeline()

// プロフィールキャッシュ
ProfileCacheManager.shared.cacheProfile(profile, for: actor)
let cachedProfile = ProfileCacheManager.shared.getCachedProfile(for: actor)
```

### レート制限対応API呼び出し
```swift
let result = try await SafeAPIExecutor.shared.execute(endpoint: "timeline") {
    try await GetTimelineApi().getTimeline()
}
```

### バッチ処理の使用
```swift
// いいねをキューに追加
BatchActionHelper.shared.queueLike(postUri: postUri, postCid: postCid)

// 即座に処理を実行
let results = await BatchActionHelper.shared.processNow()
```

## 期待される効果

### API呼び出し回数の削減
- タイムライン: 初回読み込み時のキャッシュ利用により約50%削減
- プロフィール: キャッシュ利用により約70%削減
- いいね・リポスト: バッチ処理により約60%削減

### 429エラーの防止
- レート制限管理による事前チェック
- 自動リトライ機能
- 指数バックオフによる適切な待機

### ユーザー体験の向上
- 楽観的更新による即座のUI反映
- キャッシュによる高速な画面表示
- エラー時の自動復旧

## 注意事項

### キャッシュの制限
- メモリキャッシュのため、アプリ終了時にクリアされる
- TTLによる自動期限切れ
- 手動でのキャッシュクリアが可能

### バッチ処理の制限
- 楽観的更新のため、実際のAPI呼び出し失敗時に状態の不整合が発生する可能性
- 定期処理のため、最大2秒の遅延が発生
- アプリ終了時にキューが失われる

### レート制限の制限
- 実際のAPI制限とは異なる可能性
- 他のクライアントとの制限共有は考慮されていない
- ネットワーク状況による影響は考慮されていない

2. **インテリジェントキャッシュ**: 使用頻度に基づくキャッシュ戦略
3. **リアルタイム同期**: WebSocketを使用したリアルタイム更新
4. **オフライン対応**: ローカルデータベースによるオフライン機能
5. **分析機能**: API使用状況の詳細な分析とレポート
